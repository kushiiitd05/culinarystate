# CRF top-K segmentation diagnostic (TASTEset DEV; separate v2 analysis, not part of CulinaryLinkDecision-v1)

Model: DeBERTa-base+CRF seed 1 retrained with the v1 recipe via `gpu/ner_bench/bench_train_v2.py` (new copy; v1 script untouched; `--no-test`, TEST never evaluated), checkpoint saved on the server; DEV micro-F1 0.9403 reproduces the v1 seed-1 DEV value. k-best Viterbi (`crf_nbest.py`) verified against brute-force enumeration.
Results (106 DEV docs, 2,055 gold spans): 1-best exact micro F1 **0.9403**; per-document best-of-5 oracle F1 **0.9558** (upper bound +1.55 pp, picks the best path using gold); **96.0%** of gold spans appear in at least one of the top-5 paths (1-best recall 94.3%); of the 117 gold spans missed by the 1-best path, **35 (30%)** are present in an alternative path, so a perfect span-level chooser could recover about +1.7 pp of span recall; 82 missed spans are absent from all five alternatives.
Reading: the pre-registered kill rule (stop if oracle gain < +0.3 pp) does not fire, so a `CulinarySpanDecision` lane (CRF top-K alternatives -> bounded semantic chooser) is not ruled out; realistic recovery is far below the oracle (per-span, not per-document choice; the chooser must also not damage correct 1-best spans). TASTEset DEV only; RecipeDB3 and OOF n-best (needed to train a chooser) not generated. Recorded as a diagnostic; no training started, CulinaryLinkDecision-v1 unaffected.
