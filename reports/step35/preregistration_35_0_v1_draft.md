## 1. Scope, claim boundary, and the order of work

### 1.1 What 35.0 fixes

Before any evaluation: the rungs, the tasks, the splits, the metrics, the nulls and negative controls, the primary endpoints, the promotion and failure rules, the data each rung may use (with licence scope), the environment each rung needs, and the rule that learned rungs stay deferred. The aim is the card's goal: for each level (molecule, ingredient, ingredient-state, recipe, cuisine) find the simplest representation that survives leakage-safe, non-circular, confound-controlled evaluation, and register every similarity as a **typed** function with its own null, evaluation set and split family. The two decision records of Step 35 (Level 12, Level 13) are the only route by which representations reach Step 36.

### 1.2 What 35.0 does not license

- No sentence about "flavour compatibility", "pairs well", "tastes like" or "substitutable" from chemistry or co-occurrence (Spence 2020; structural != sensory; presence != abundance != importance).
- No learned rung (35g) and no process-response rung (35f) in this document's scope (sections 13 and 14).
- No fused similarity scalar; no weights; no "the similarity" column anywhere (G35-SEP).
- No release of FlavorGraph-derived per-ingredient profiles (licence scope, section 3); their outputs are written only to a git-ignored location (section 15, `THR-35P-31`).
- No arm, comparator, mapping, tie-breaker or prior may use FlavorGraph edges or embeddings, KGE `ING_CO_OCCURS` (either origin) or any Recipe1M-derived statistic (rule BAN-35-1, section 5.3, `THR-35P-38`).
- No SOTA/"first"/"beats X" statement (H6). Nothing here is a result.

### 1.3 Order and the meaning of "start now" (R-10)

35.0 -> {35a, 35b, 35c, 35d} in parallel -> 35e -> 35h (decision records v1). Later: 35f (needs Steps 15, 27, 30, 33) -> 35h v2. 35g only on explicit failure evidence plus a non-circular target (section 14). The minimum viable Step 35 is 35.0, 35b, 35c, 35e, 35h (card).

"Start now" means the input artefacts exist. It does **not** authorise an evaluation run: **no metric on real labels, real profiles or real recipes is computed before this document and its 01.6 rows are signed and hashed (G35-PRE, `THR-35P-01`)**; the evaluation entry point must refuse to run when the hash is missing or differs (an engineering control, to be built). Permitted before signature (`THR-35P-02`): writing specs, unit tests on synthetic fixtures, decoding tests on published example fingerprints, environment pinning, and descriptive count tables of inputs (already read, section 2). Permitted after signature but before 07I-S exists: *descriptive* recipe/cuisine runs on the conservative grouping, labelled `DESCRIPTIVE_CONSERVATIVE_GROUPING` and not eligible as headline (card: headline recipe/cuisine claims wait for the 07I-C `split_group_id`; `THR-35P-03`).

### 4.4 Labels, tasks, baselines, metrics

- **Label set (`THR-35P-04`; negatives and source confound `THR-35P-36`):** `MOL_HAS_TASTE` edges with `status = ACTIVE` only; DEPRECATED edges excluded. Raw strings map to classes by a reviewed table (proposed rule: Sweetness/Sweet -> SWEET; Bitterness/Bitter and graded qualifiers "Slightly bitter", "Somewhat bitter" -> BITTER; Sour/Sourness -> SOUR; "Bitter/Sweet" and "Bitter; Sweet" -> both SWEET and BITTER; Multitaste, Miscellaneous, Tastelessness, "Hot burning", "Heating, pungent, and tingling" and unparsed compound strings -> OTHER, not scored). The map is a file reviewed by a chemistry-aware reviewer before signature; it is fixed before any model runs. Tasks are **one-vs-rest binary** per scored class (a molecule can carry several tastes).
- **Confirmed negatives only (`THR-35P-36`, D35-18).** The labels are positive-unlabelled data: "no edge for class c" does not mean "not c" (bittersweet curates only bitter and sweet plus explicit "Non-bitter" strings; ChemTastesDB covers more classes). For a class c, positives = molecules with an ACTIVE edge mapped to c; negatives = only molecules with an explicit negative for c (for example a "Non-bitter" string) **or** molecules from a source database that assays c according to the reviewed assay-coverage table (database x class: ASSAYED / NOT_ASSAYED / UNKNOWN; UNKNOWN is treated as NOT_ASSAYED). Every other molecule is **excluded** from the task for c and is never counted as a negative. "Tastelessness" is not used as a negative until the reviewer decides it.
- **Source-database confound (`THR-35P-36`).** The source database predicts both label availability and chemotype, so a structural classifier can score by recognising the database. Mandatory: NC35-14 (source-database-only baseline: predict the class from the source-database indicator alone), per-source-stratified AUPRC reported next to PE-35a, and the label `SOURCE_DB_CONFOUNDED` (no headline) when the strongest explicit arm minus NC35-14 does not have a lower 95% bound above the `THR-35P-08` AUPRC margin. 71% of ACTIVE edges come from one AGPL-3.0 source (section 2), so this control is not optional.
- **DEPRECATED-edge audit (before signature).** The 204 DEPRECATED ChemTastesDB edges carry one reason string ("no longer derived", 204 of 204). A human establishes the underlying reason (re-derivation, mapping change or label conflict) and the counts by reason are recorded as `DESCRIPTIVE_COUNTS_SEEN`; molecules whose labels conflict are listed and handled in the map review.
- **Scored classes (`THR-35P-05`):** a class is scored on a split only if it has >= 30 positive molecules **and >= 30 confirmed-negative molecules (`THR-35P-36`)** and >= 10 distinct split clusters (cluster = the `S-mol-cc` component) among positives, and at least 5 positive molecules in the test side of at least 3 of the 5 folds; otherwise the class is `NEED_DATA` for that split. Which classes pass is a result; counts per source database are reported with every class.
- **Arms:** label prior; kNN-Tanimoto (PubChem-881, k in {1, 5, 15} fixed grid, k chosen on dev folds only); descriptor-lite logistic; 881-bit logistic and random forest; stand-in GBM on 881 + descriptors. Arm hyper-parameter grids are fixed in the spec before signature; tuning uses inner folds, never test folds (`THR-35P-07`).
- **Metrics (card):** macro AUROC and macro AUPRC (AUPRC primary for rare labels), per-class F1, ECE and Brier, and the OOD gap (random - `S-mol-cc`). 
- **Primary endpoint PE-35a (`THR-35P-17`):** macro-AUPRC over scored classes on `S-mol-cc`: strongest explicit arm minus label prior, and strongest minus kNN-Tanimoto, paired cluster-bootstrap difference with 95% CI; per-source-stratified AUPRC and NC35-14 are reported next to it (`THR-35P-36`). Everything else is secondary/exploratory and labelled.
- **Structural x sensory separation test (feeds G35-SEP).** "Structure -> taste" is the separation test between the STRUCTURAL and SENSORY notions; it is the evaluation set of neither (8.2). Report, per scored class, how well Tanimoto-881 nearest-neighbour taste agreement beats the label prior on `S-mol-cc`, i.e. whether structural neighbours share taste class. Pre-registered reading: if kNN-Tanimoto-881 beats the label prior by more than the `THR-35P-08` AUPRC margin (lower 95% paired cluster-bootstrap bound) for a class, that class is reported as "structure predicts taste here"; otherwise as "no evidence that structural neighbours share taste class". Either outcome is a result and is reported; STRUCTURAL and SENSORY remain separate registry rows regardless (the law forbids substituting one for the other; it is not an empirical prediction).
- **Own evaluation targets that use neither taste labels nor recipes (8.2; descriptive, no pass value).** STRUCTURAL (molecule): **ST-1** connectivity-sibling retrieval: for each molecule in the 120 multi-molecule 14-character blocks (271 molecules), rank all other molecules by tau881 and score Recall@k (k in {1, 5}) of its block siblings against a random-ranking null (unsupervised, no split needed; ties between identical fingerprints are broken at random and counted); **ST-2** descriptor reconstruction: kNN-tau881 regression of the six PubChem descriptors on `S-mol-cc` against the training-mean null (R2 and MAE per descriptor). SENSORY (molecule): **SE-1** label reproducibility: for molecules labelled by >= 2 independent source databases, agreement of their taste-class sets between databases (Jaccard, and per-class Cohen's kappa) against a shuffled-label null; `NEED_DATA` if fewer than 30 molecules have >= 2 sources.

### 4.5 Splits for 35a (`THR-35P-06`, `THR-35P-35`, `THR-35P-39`)

`S-mol-conn`: groups = 14-character connectivity blocks; zero full-InChIKey overlap **and** zero 14-character overlap across train/test (G35-0). `S-mol-clu881`: leader (Butina-style) clustering on 1 - Tanimoto-881 at tau_cluster, which is **derived by a label-free procedure** (`THR-35P-35`): tau_cluster = the 99th percentile of tau881 over 20,000 random molecule pairs drawn (fixed, recorded seed) from the 1,726 molecules, clipped to [0.60, 0.85]; sensitivity grid tau_cluster - 0.05 and tau_cluster + 0.05. It is computed **before any label join**, reads no label, score, fold size or model output (so it is not tuning), and its value and seed are written into the hashed split manifest. Substructure-key Tanimoto runs high for small flavour molecules, which is why the value is anchored to the fingerprint's own distribution and not to a round number. Cluster-disjoint 5-fold. `S-mol-cc` (primary): connected components of the union of the two groupings (clustering is computed on all 1,726 molecules; the 30% rule below is evaluated on the scored molecules). Reference: random 5-fold. At least 5 seeds x 5 folds. **Degenerate-split rule:** if the largest `S-mol-cc` component holds more than 30% of the scored molecules, the split is declared `DEGENERATE`, the result is reported as such, and tau_cluster is **not** retuned; the headline then falls back to `S-mol-conn` plus random with a "weak split" label. The threshold is never chosen to hit a fold size or a score.

**Multi-component records (`THR-35P-39`).** The first InChIKey block hashes the connectivity of all components, so a salt or mixture does not share a block with its parent and `S-mol-conn` is not salt-blind; salt twins of one parent could straddle train and test. 15 of the 1,726 canonical SMILES contain `.`. Until a structure toolkit is approved (D35-2, D35-21) these records are flagged `MULTI_COMPONENT`, **excluded from every scored set and listed in the split manifest**; afterwards each is grouped with the InChIKey block of its largest organic fragment computed with the pinned toolkit. NC35-15 (planted salt pair) must be flagged by the split auditor.

### 4.6 Nulls and controls for 35a

Label-permutation within cluster (expect AUROC near 0.5); shuffled-label fit through the same pipeline; random-embedding baseline; planted-pair test of the split auditor (a planted molecule sharing a 14-character block across train and test must be flagged; a planted salt twin must be flagged, NC35-15); source-database-only baseline (NC35-14); stability across the tau_cluster grid; replicate on the 881-only and descriptor-only arms to separate fingerprint from descriptor signal.

## 5. Rung 35b — ingredient chemical profile `x_ij` and aggregator ablation

### 5.1 The tiered record (presence != abundance != importance)

`x_ij` = {tier in PRESENCE | MEASURED_CONC | THRESHOLD | OAV_DERIVED, value or UNKNOWN, unit, basis, matrix, state/form, study_id, source_family, licence_scope, evidence_ids}. Today: PRESENCE 29,656 ids = 31,334 ledger lines (state unspecified, ingredient level); MEASURED_CONC 219 (polyphenols, with basis and state); THRESHOLD 0; OAV_DERIVED 0 (OAV only when concentration and threshold share a matrix; none exists, so **OAV-weighted representations are impossible and ingredient-level SENSORY is UNSUPPORTED**). Rules (`THR-35P-32`; licence scope `THR-35P-31`):

1. Tiers are never merged into one set or vector. PRESENCE-tier similarity uses PRESENCE only; MEASURED_CONC is a separate, descriptive analysis in its own compound space (polyphenols) and never mixed with FlavorGraph presence.
2. A PRESENCE profile is **not a raw/cooked state profile**; EVD-derived rows with a state are not compared with it.
3. UNKNOWN concentration/threshold/state is masked, never 0 and never 1.
4. Every ingredient has a coverage record {n_compounds, n_sources, n_measured, coverage_class}; the profile universe is the 298 ING with PRESENCE rows, out of 2,110 distinct ING (the card's coverage limit: 313 profiled at all); the join ING <-> FlavorGraph node is audited on 50 crosswalks by Parv (about 2 h, card). **Selection effect:** the 298-ingredient universe exists because FlavorGraph (built from Recipe1M) links 417 ingredients to compounds; Recipe1M-frequent ingredients are more likely to be linked, so TASK-ING-A queries are biased toward them (section 16).
5. Ingredients with fewer than **5** PRESENCE compounds are kept in the record but excluded from the *headline* pair metrics and reported as `SPARSE` (`THR-35P-32`); 10% of the 298 have 3 or fewer.
6. Ingredients with **identical PRESENCE sets** (FlavorDB-derived profiles often copy one generic compound list to related entities) are counted and reported; they are merged into one cluster in `S-ing-clu` and treated as a single profile in the nulls and in TASK-ING-A query sets (`THR-35P-43`), because identical sets score 1 for CHEMICAL and STRUCTURAL, distort the Curveball null and create near-duplicate queries.

### 5.2 Scores

On sets F_i of PRESENCE molecule ids (ACTIVE edges only):

| Arm | Definition | Notion |
|---|---|---|
| E0 `n_ij` | abs(F_i AND F_j) | CHEMICAL |
| Jaccard | abs(F_i AND F_j) / abs(F_i OR F_j) | CHEMICAL |
| Ochiai | n_ij / sqrt(abs(F_i) abs(F_j)) | CHEMICAL |
| IDF-overlap | sum over c in F_i AND F_j of w_c / sum over c in F_i OR F_j of w_c, with w_c = max(0, ln(N / (1 + df_c))), N = 298, df_c over the 298 profiles (`THR-35P-12`; the card's formula clamped at 0 because df = N gives a negative weight) | CHEMICAL |
| Null percentile | share of null n_ij <= observed under the degree-preserving null (5.4) | CHEMICAL (calibrated) |
| Kernel-mean (E1 variant) | (1 / (abs(F_i) abs(F_j))) sum over a in F_i, b in F_j of tau881(a,b) | STRUCTURAL (ingredient) |
| Symmetrised best-match | 1/2 (mean over a of max over b tau881 + mean over b of max over a tau881) | STRUCTURAL (ingredient) |
| Top-k mean | mean of the k largest tau881 over the pair grid, k in {1, 3, 10} fixed | STRUCTURAL (ingredient) |
| Balanced OT | ablation arm only, flagged "no food-specific evidence, SSOT 'Unverified' L8868"; waits for rdkit and is not part of the primary comparison | STRUCTURAL (ingredient) |

IDF-overlap is UNKNOWN (masked, not 0) when the sum of w_c over F_i OR F_j is 0 (a union of ubiquitous compounds only); the number of masked pairs is reported (`THR-35P-12`). All ECFP-based set arms wait (4.2). The aggregator ablation reports, per arm, the cardinality slope and the profile-size-stratified metrics (SSOT: aggregation choice changes the answer more than the molecule kernel).

### 5.3 Tasks (non-circular by SSOT §133.2 and §190.16)

- **TASK-ING-A (primary; the CULTURAL notion's own target and a cross-notion association test for CHEMICAL and STRUCTURAL): held-out recipe co-occurrence.** For each profiled ingredient i that has >= 10 relevant partners, rank the other profiled ingredients by the score; a partner j is *relevant* if i and j co-occur in >= c_min = **5** held-out (test-partition) recipes with NPMI >= 0, computed **only inside the test partition** of the `S-rec-grp` split (`THR-35P-18`). TASK-ING-A asks whether chemistry-derived similarity predicts a cultural statistic; it is **not** CHEMICAL's or STRUCTURAL's own evaluation set (8.2). Chemistry arms use no recipe data; comparator arms that use recipes (frequency-only popularity, co-occurrence-from-train) are fit on the train partition only. **Rule BAN-35-1 (`THR-35P-38`, D35-20):** no arm, comparator, mapping heuristic, tie-breaker or prior may use FlavorGraph ingredient-ingredient edges, FlavorGraph node embeddings, KGE `ING_CO_OCCURS` edges of either origin or any Recipe1M-derived statistic, because FlavorGraph and its edges derive from Recipe1M, whose recipes may overlap the **test partition** of `S-rec-grp` (not only "the whole corpus"); only IMAP PRESENCE ingredient -> compound rows enter the chemistry arms, and the evaluator lints every arm's input manifest against this ban (NC35-17). Metric: MAP@10 (and Recall@10), macro over query ingredients, CI by ingredient-cluster bootstrap (`THR-35P-17` = PE-35b). **Never** use KGE `ING_CO_OCCURS` edges (either origin) as relevance: the corpus-mined ones were mined across the whole corpus and the FlavorGraph ones derive from Recipe1M. This row of the SSOT table ("classical n_ij -> held-out recipe co-occurrence", acceptable) is the only reason the task is allowed; the headline sentence is limited to "shared-compound overlap does / does not predict held-out co-occurrence", never "flavour". Results are reported pooled **and per source family** (a source-stratified test partition is about 85% Food.com when pooled).
- **TASK-ING-B (proxy, never headline): ingredient category retrieval** against `ING_HAS_CATEGORY` (631) and `ING_COSYLAB_CATEGORY` (964; RecipeDB2-derived, licence ASSUMED), cluster-disjoint folds; flagged weak/proxy in the circularity audit (G35-CIRC).
- **TASK-ING-A-cold (secondary endpoint PE-35b-cold, `THR-35P-40`, D35-23).** TASK-ING-A admits only queries with >= 10 relevant partners of >= 5 test co-occurrences each, i.e. frequent ingredients, where popularity comparators are strongest and chemistry is least needed. Cold-start test: a seeded random 20% of the profiled ingredients, stratified by profile-size quartile (not by frequency), are cold-start entities (`S-ing-cold`); every recipe that contains a cold entity is removed from the train partition. A query = a cold entity with >= 3 relevant partners, a partner being relevant if it co-occurs with the query in >= 2 test-partition recipes with NPMI >= 0 (computed inside the test partition, as in `THR-35P-18`). Co-occurrence-from-train carries no information on a cold query; frequency-only (partner popularity) and cardinality-only comparators remain. PE-35b-cold = MAP@10 of IDF-overlap minus the better of frequency-only and cardinality-only on these queries; a breakdown by test-partition frequency tertile is reported. Secondary, labelled as such.
- **Forbidden headline:** n_ij -> n_ij retrieval (circular, SSOT §133.2).
- Process-state discrimination (raw vs cooked) is **35f**, not here.

### 5.4 Nulls, controls, diagnostics

- **Degree-preserving null (`THR-35P-13`):** Curveball trades on the ingredient x compound presence matrix, 5 x (number of ingredients) trades per randomisation, 1,000 randomisations; stability check: mean `n_ij` per size bin unchanged (within the Monte-Carlo SE) when trades are doubled. A size-preserving hypergeometric null is reported alongside as a cheaper reference. These 1,000 randomisations calibrate the null percentile of a score; they are **not** the draws behind a BH-corrected test (`THR-35P-37`, 7.3).
- **Cardinality slope (`THR-35P-14`):** Spearman rho between a pair score and sqrt(abs(F_i) abs(F_j)) over the pair set, with an ingredient-cluster bootstrap CI, per arm. If |rho| > 0.3 and it persists under matched-coverage resampling (4 quantile bins of profile size, 1,000 resamples; `THR-35P-15`), the arm is `COVERAGE_CONFOUNDED` and gets no headline (card G35-COV).
- **Stability (`THR-35P-16`):** random compound dropout of 10%, 25% and 50% per profile; neighbour-overlap@10 against the full-profile ranking.
- **Controls:** cardinality-only baseline (rank partners by abs(F_j)); frequency-only baseline; shuffled-compound control (compounds permuted within the profile universe preserving profile sizes); top-k ingredient removal; odourless-only control (NEED_DATA: needs odour labels); BAN-35-1 input-manifest lint (NC35-17).
- **Splits:** `S-ing-clu` (ingredient clusters = connected components over ING `parent_ids` and `ING_PARENT` edges, so raw/cooked/cultivar variants stay in one fold) and `S-ing-cold` (cold-start entities, defined above and in section 9) for any task where a model sees ingredients and for PE-35b-cold; the chemistry arms themselves are unsupervised. Recipes in TASK-ING-A use `S-rec-grp`.

### 7.2 Labels, ontology and the cuisine = source confound

Cuisine labels exist for 9.81% of recipes, 0% for Food.com, 59% of them are "American", and 85.6% of all labelled recipes come from Gutenberg segments; the card records 153 of 156 labelled sources as single-label, so **cuisine is close to source**. A high rank agreement between two notions is a finding to report, not hide. The molecule-level structural-vs-taste agreement of 4.4 is the first separation test.

## 11. Statistics, primary endpoints, and the promotion rule

- **One primary endpoint per rung** (to limit forking paths; `THR-35P-17`): PE-35a, PE-35b (TASK-ING-A MAP@10 of IDF-overlap vs the better of frequency-only and cardinality-only; a cross-notion association endpoint), PE-35c, PE-35d (defined in `THR-35P-41`). PE-35b-cold (`THR-35P-40`) is a labelled **secondary** endpoint. 35e has no endpoint (structural gate). Everything else is exploratory and says so.
- **Uncertainty (`THR-35P-10`, `THR-35P-11`):** paired cluster bootstrap of differences, B = 10,000; cluster = `S-mol-cc` component / ingredient cluster / split group / source; >= 5 seeds x >= 5 folds; with fewer than 20-30 clusters use a cluster sign-flip permutation test; Benjamini-Hochberg q < 0.05 within each pre-registered family (molecule tasks; ingredient tasks; recipe tasks; cuisine tasks), where the null-draw count behind any Monte-Carlo p-value follows `THR-35P-37`; effect sizes with CIs always, never a bare p-value.
- **Promotion rule (card; SSOT §183.3, §194.3, G13-1, G3; `THR-35P-08`, `THR-35P-09`):** a more complex rung is promoted only if the lower 95% bound of its paired cluster-bootstrap gain over the strongest simpler comparator exceeds delta on >= 2 task families and 2 split types and survives the frequency/size/source controls; delta = 0.01 macro-AUROC and 0.02 macro-AUPRC for molecule tasks (SSOT G3, "proposed"), 0.01 Recall@10 for retrieval. "Strongest simpler comparator" is fixed by the dev partition before the test partition is touched.
- **Run manifest and compute reporting (`THR-35P-34`):** input hashes, package versions, seeds, parameters, wall time and RAM per arm; stand-in comparators carry their stand-in label.
- **Interpretation guard:** with 298 profiled ingredients, 603 labelled molecules and a few clusters, expect wide intervals; absence of evidence is reported as such (DATA-BLOCKED is an allowed decision-record state, SSOT L13275).

## 14. Learned rungs (35g) stay DEFERRED (`THR-35P-29`)

**Rule.** No 35g experiment is run, scheduled, or pre-registered by this document. Learned rungs may start only when **all** hold:

1. **LR-1** the explicit rungs for that level were evaluated under this signed pre-registration and their results are written into a draft decision record (v1);
2. **LR-2** an explicit rung left a *documented* held-out failure against a failure criterion registered in advance (for example the strongest explicit arm's lower CI bound on its primary endpoint below a registered floor, or a documented confound a learned model could address); "we want a larger model" is not a failure;
3. **LR-3** a non-circular supervised target exists (not n_ij; not co-occurrence trained and evaluated on co-occurrence; SSOT §133.2, §191.9); 
4. **LR-4** training data are licence-cleared (recipe models train on `training_allowed = YES` rows only; molecule/label licences recorded);
5. **LR-5** a signed addendum (35.0-A1) to this pre-registration, human approval (H4 for new registry statuses; H3 above the compute threshold), matched-capacity and parameter-matched controls (G5), and "E7 may not be reported without E0-E3 on the identical split" (SSOT L8489-8510).

**Boundary of "learned"** (closing loopholes): anything with parameters fit to a task objective to produce a representation, any pretrained encoder or weights (including frozen encoders used as feature extractors), any node2vec/metapath2vec/graph or KG embedding (SSOT E4), and any dimensionality-reduced or latent embedding (PCA, SVD/LSA, autoencoder, word2vec) are **35g-class**. Explicit-feature supervised classifiers (logistic regression, random forest, gradient boosting on fingerprints, descriptors, incidence or TF-IDF) are *baselines*, not learned representations. TabPFN is a pretrained-prior tabular classifier: optional comparator, off by default, needs a dependency and licence row; it is never a representation rung. Learned rungs are not required for PASS and a learned rung that fails promotion leaves the explicit rung as the default (a valid negative result).

## 16. Risks and honest limitations

1. 298 profiled ingredients and 603 labelled molecules are small: intervals will be wide and several classes will be NEED_DATA; that is a finding, not a defect.
2. FlavorGraph presence profiles are coverage-confounded by construction (417 of 6,653 FlavorGraph ingredients have compound links; 110 of those are not mapped to ING); the cardinality gate may flag every arm.
3. The taste labels are categorical class memberships from curated databases of mixed provenance (one ASSUMED licence); they are a coarse sensory proxy, not intensities, and graded qualifiers are collapsed by a proposed map.
4. Without rdkit the molecule leaderboard is incomplete by design and the SSOT G2 reference baseline is not available.
5. Recipe incidence rests on exact-alias linking with unknown coverage; Food.com licence/authority is unverified; BBC is local-only.
6. Cuisine labels are dominated by Gutenberg-sourced "American"/"English"; the headline set may be empty.
7. TASK-ING-A uses recipe co-occurrence as the relevance signal; it is a cultural statistic and the only permitted sentence is about prediction of held-out co-occurrence.
8. Several thresholds (c_min, min support, trade count, the 20% cold-start fraction, 20,000 sampled pairs) are plausible round numbers, not derived values; they are registered *before* any result, which is their only protection. tau_cluster is now fixed by a label-free procedure (`THR-35P-35`), not by a round number.
9. The registry v2 id scheme and statuses need H4; the nine-notion mapping of SIM-13 (reaction-center) has no home among the nine.
10. **Taste labels are positive-unlabelled and source-confounded.** Only confirmed negatives are used (`THR-35P-36`), which shrinks the scored-class set; 71% of ACTIVE labels come from one AGPL-3.0 database; the 204 DEPRECATED edges have an unexamined reason.
11. **Recipe1M contamination and profile-universe selection.** FlavorGraph edges and embeddings derive from Recipe1M, whose recipes may overlap the test partition; BAN-35-1 removes them from every arm and comparator (a weaker comparator set is accepted), and the 298-ingredient universe was itself selected by FlavorGraph's Recipe1M frequency, so TASK-ING-A queries are biased toward Recipe1M-frequent ingredients. PE-35b-cold (`THR-35P-40`) is the partial check.
12. **Salts and mixtures.** 15 of 1,726 molecule records are multi-component and are excluded from scored sets until a structure toolkit is approved.
13. **Identical profiles.** FlavorDB-derived profiles may repeat one generic compound list across related ingredients; they are merged for splits and nulls (`THR-35P-43`).
14. **Weak structural/sensory targets.** STRUCTURAL has only structure-only targets (ST-1, ST-2) and no external ingredient-level target; SENSORY molecule evaluation is label reproducibility across databases and may be NEED_DATA. This is deliberate: it keeps the notions separate rather than scoring both on the same labels.
