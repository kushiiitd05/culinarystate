## 3. Design notes and numbers

**Row 2, zone field.** For a half slab, xi = x/L in (0, 1) (0 centre, 1 surface), Gauss-Legendre nodes and weights give mean_i w_i f(xi_i) for the volume mean (exact to degree 15 for 8 nodes). Node temperatures use the same boundary, h, alpha, k, T_0 as the core (the capped boundary in L2). Histories sit on a graded time grid (48 steps, fine early, because a node next to the surface moves within seconds) stored with the histories; rounding is 0.01 C (the stored node doses reproduce the recomputed ones within 0.2 %). Doses use the trapezoid on the dose RATE, not on the temperature.
- **Accuracy (not a validation against food):** against a 64-node, 1,200-time reference over 144 cases (half-thickness 0.5-12.5 mm, h 10-1,500, 2-45 min, boundary 100 / 121 / 190 C), 8 nodes: median relative error 1.6e-4, maximum 0.34 %; 6 nodes: maximum 3.2 % (hence default 8; the layer accepts 6, 7 or 8 only). Tests pin 1 % for five representative cases.
- **FINAL-SCI hand calculation reproduced** (1 cm dice, bath 98 C, Bi = 6, z = 33): zone-mean dose / dose at the volume-average temperature = 1.99 at 0.5 min, 1.33 at 2 min, 1.05 at 5 min, 1.01 at 15 min; the factor grows as z falls (test `test_smaller_z_widens_the_gap`). The review said "about 2x early, about 1.1x at 2 min"; this calculation gives 1.3 at 2 min.
- **Effect on the corpus** (zone-mean dose over `cook_value_at_volume_avg_t_min`, moist and dry class together, counts-only quantiles in `zone_field` of each report): FOODCOM TYPICAL p50 1.004, p90 1.019, p99 1.58, max 10.8; GENTLE p50 1.018, p90 1.93, p99 2.48, max 20.7 (short GENTLE durations). Over the core dose: TYPICAL p50 1.023, p99 4.3, max 81.8. The median effect is small because most events are long and near-isothermal; the tail is where the old field was wrong, as FINAL-SCI predicted.
- **For M3:** `PD.zone_mean_survival(hist, k_of_T)` computes the mass-average retention from the stored `zone_nodes` (`weights`, `times_min`, `temps_c`) for any first-order rate; a test shows mean exp(-kF) >= exp(-k mean F) (Jensen), i.e. retention at the mean dose is not the mean retention.

**Row 3, cap.** Stated aqueous liquid = media WATER, LIQUID, LIQUID_PARTIAL, WATER_PRESSURIZED, WATER_BATH_SEALED with an L1 temperature basis TEXT_STATED or CARRIED_SETPOINT. An oil or oven temperature never lifts the cap (the review endorses the oil result: 1 cm dice deep-fried reach about 94 C). A stated pressure-vessel temperature is not cut to the 108.4 / 115.2 / 121.0 bracket. The lift sets the cap equal to the stated temperature, so the invariant becomes "no moist zone of a dilute water phase exceeds max(T_boil, stated liquid T) + eps". Solute-rich classes are SWEETENER (dry class, so single-class lots stay uncapped) and CONDIMENT (ambiguous class, capped, flagged lower estimate). A roux (CEREAL + FAT_OIL) stays capped because flour is an ambiguous class, not a dry class; praline-like lots (NUT_SEED + SWEETENER) are DRY.

**Row 4, F0.** The canner temperature comes from PC-002 (GENTLE 108.4 / TYPICAL 115.2 / INTENSE 121.0), a stated temperature is kept. A "sterilise" verb in a pressure canner is not the canning step (PROC-000131), so it gets the conditions only. For the non-canner branch missing inputs still give SCENARIO_UNKNOWN, as before. The retired NH-010 was never read in v03.

**Row 5, acid.** The acid branch needs neither a size nor a diffusivity, so 999 events that were SCENARIO_UNKNOWN (no cut size) are now QUALITATIVE: FOODCOM 574 + 168, GUTENBERG_SEGMENT 163 + 83, WIKIBOOKS 9 + 2 (a status shift, not new numbers; section 6).

## 7. Open questions and limits (nothing here is decided)

1. **Stated liquid temperature above 150 C is probably an L1 mis-association.** The rule as specified ("never cap below a text-stated liquid temperature") uncaps all 520 events; 197 of them (191 + 4 + 2) state more than 150 C for a boil, simmer or similar water medium, far above candy-syrup temperatures. 7 FOODCOM events with a computed core are in that bucket (core up to 204 C): this re-introduces, for a handful of events, the overshoot the cap was added to remove. Likely cause: an oven or pan temperature in the same sentence as a water verb. Choices for a human: (a) keep the rule, treating the bucket as a visible L1 problem; (b) bound the lift by a sourced maximum aqueous boiling temperature (candy-stage literature; none is recorded here, so none was invented); (c) require sentence scoping in L1. The counts by bucket are in every v03 heat report under `counts.stated_liquid_above_tboil_by_stated_c`.
2. **Member groups are not in the existing L1 records.** L1 emits `matrix_class` only for single-group lots, so rows 3b and 3c act only on single-class lots until L1 emits all groups. L2 already reads an optional L1 input `matrix_groups` (`{"value": [group, ...], ...}`). One-line L1 patch for the L1 owner (not applied; `condition_binding.py:187-188`): after `groups = self._groups(g, ev.consumes)` add `if groups: inp["matrix_groups"] = _known(sorted(groups), "FOOD_GROUP")`. A scratch run (RUN-S177-PHYS-011, repo L1 code untouched, 1,000-recipe sample, 2,820 heat events) shows the effect: status counts identical; lot-has-solute-rich-member lower-estimate flag 23 -> 293 of 1,275 capped events; `MATRIX_UNKNOWN_MOIST_ASSUMED` 950 -> 410; `MATRIX_AMBIGUOUS_MOIST_ASSUMED` 104 -> 155; every-member-dry (uncapped) lots 58 -> 60 (2 multi-member). The group labels themselves come from the AI-matched ING category and are noisy (examples in the ING ledger: "sugar snap peas" is SWEETENER, "caster sugar" is HERB_SPICE), so these flags are diagnostics, not composition. The SR water < 15 g/100 g criterion of row 3c is not implemented (it needs the composition layer, which this lane must not import).
3. **Solute-rich classes** (SWEETENER, CONDIMENT) are an AI recall (`SOURCE_UNVERIFIED_AGENT_RECALLED`); the magnitudes quoted in the reworded §284.3 (jam 104-105 C, candy syrups 105-150 C, heavy brine near 108 C) come from the review text and are tagged as unsourced recall there. No boiling-point-elevation model or constant was added.
4. **The GENTLE-INTENSE bracket does not yet include a fixed-100 C-surface end or a wet-bulb end** (FINAL-SCI verdict, last paragraph). Not part of the five rows; not done.
5. **Row 9 is text only.** No stirred / unstirred / flipped geometry exists in code (the slab is two-sided by construction, which is the stirred end). Cube, cylinder and sphere shapes are still not implemented.
6. **F0 low-acid check.** The canner branch assumes a low-acid food without checking (flag `LOW_ACID_FOOD_ASSUMED_NOT_CHECKED`); the pH registry of the composition layer could gate it later. FOODCOM has no pressure-canning event with a duration, GUTENBERG 4, WIKIBOOKS 0, so the canner path is exercised mostly by tests.
7. **Coverage shift, not new numbers.** 999 non-heat events (full runs; one more in the 1,000-recipe sample) move from SCENARIO_UNKNOWN to QUALITATIVE_FLAGS_ONLY because the acid branch needs no size; any coverage headline must say "qualitative", not "computed".
8. **Record size.** The node histories add 0.7 GB to the three heat families (3.1 GB against 2.4 GB). A later model that needs fewer numbers can use `ScenarioLayer.load(n_nodes=6)`.
9. **Tool conventions.** `--compare-prev-l2` expects the previous per-event files under the same file names and in the same order as the L1 files (true for every S176 v02 directory used here; misaligned or missing files are counted, not hidden).
